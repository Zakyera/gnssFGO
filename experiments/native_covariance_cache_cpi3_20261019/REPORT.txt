What changed
------------
The existing native Gaussian covariance provider now lazily assembles, rank-
checks and factorizes the native system once per queried committed epoch.
Every pair then queries that same Gaussian Bayes tree. Its per-pair joint
covariance, current-chart transport and full6x6 relative Schur extraction are
unchanged. No additional nonlinear residual/Jacobian evaluation or GPU call.
This caches computation, not the covariance value across source updates.

Preparation belongs to immutable committed State. A newly staged State clears
its own preparation immediately. Successful commit swaps in this fresh State;
retirement/equation/chart changes therefore cannot inherit an old tree. Reset
starts empty. Failed staging, mismatched commit and abort preserve the previous
committed state and cache. Failed rank/elimination installs no prepared tree.
Caller output remains unchanged on query failure; no MAIN covariance fallback.
Queries remain single-threaded, as in the existing observer contract.

theta() retains the same validity check and returns a Values copy, but no longer
clones a Gaussian graph solely to check that the epoch exists. This was another
redundant per-pair preparation operation, not a mathematical change.

The change is exclusively in NativeGaussianHistory.h/.cpp. ShadowObserver,
rank certificate, fixed-lag wrappers, CP-I1 revision bridge, source means,
revision identity/timing, source-to-source classic CBS and gnssFGO are unchanged.
One preparation does NOT mean zero per-pair linear algebra: joint extraction,
12D validity checking, transport and relative Schur work still execute per pair.
