MAIN FINDINGS
=============
1. The first ON ordinary solve starts with285 nonzero native visual factors.
   Its resulting poses make the next refresh use266: a real change in the
   reconstructed native Gaussian equations, not just a trajectory plot or an
   error-report counter. OFF uses285 at both stages.
2. At the observed ON post-step states, clearing the triangulation cache does
   NOT restore the lost support. Native maximum-reprojection/rank rules explain
   the resulting classifications. These are unchanged observations becoming
   ineffective backend factors, NOT frontend features disappearing.
3. There IS a separate reproducible numerical sensitivity: with noisy saved
   observations, native algebraic DLT triangulation and its rank/reprojection
   decisions depend on the world ORIGIN. A pure world rotation passes; moving
   only the origin changes some track classifications. Independent NumPy SVD
   reproduces all4056 classifications and3677 returned points, max6.34e-11m.
4. None of this yet proves the cause of the full CBS-ON zigzag or justifies
   changing weights, disabling visual rejection, or promoting a solver fix.

======================================
At ON after-ordinary / refresh-theta / final-estimate, warm and freshly cleared
triangulation give the SAME validity and Gaussian matrices. The large observed
post-step loss is therefore not repaired by recomputing those landmarks at
those exact states.

However, at the initial ON owning theta, clearing the cache changes factor571
fromvalid todegenerate. OFF's own initial-theta check changes571 valid->outlier.
The saved retriangulationThreshold=.001 allows landmark reuse after small pose
changes. We have not isolated that initial cache difference with an optimizer
ablation. Do NOT conclude that all cache-history effects are absent.

Across25688 evaluations,598warm/cold status differences include synthetic
fractional probes along observed state changes and repeated observations; they
are NOT598 actual runtime failures. Intermediate fractions are diagnostic
samples, not optimizer iterates. Very large relative matrix ratios occur when
one factor becomes exactly zero; do not present these as global solver error.

OFF and ON owning theta/caches need not be identical, even though CP52 verified
the SAME supplied initial values and non-CBS factor functions for its clean A/B.
The analysis.json field initial_OFF_ON_visual_status_and_keys_equal compares
slots at those different owning-theta snapshots and is false; it is NOT a
finding of different input data, physical frames, or corrupted observations.
Function-identity multisets were already checked in CP52 (including duplicate
identical factors); do not infer identity solely from equal counts or slot IDs.

3. FAILED COORDINATE CHECK — REPRODUCED NUMERICAL SENSITIVITY
===========================================================
A physical world-coordinate change should not alter the camera observations
or relative camera geometry. Original strict test applied one nonidentity
rotation plus translation and required unchanged status and point equivariance
within1e-6m. It failed immediately on saved noisy data, while exact-observation
fixtures passed. Original failure and stopped-container cleanup are retained.

Fresh measurement retained the SAME failed thresholds and explicitly reports
passed=false. It counted89status changes across2704state/factor comparisons and
2210point discrepancies above1e-6m. These include repeated states, not89distinct
tracks or runtime events. The combined-transform worst point discrepancy was
1.107m. No graph optimization used these artificial coordinates.

A separate decomposition identifies world translation, not a body-frame flip:
  pure rotation RzRyRx(.2,-.15,.3rad): zero status changes in1352comparisons;
    max valid-point discrepancy1.50e-12m.
  pure translation [3,-2,1]m, with all camera poses translated consistently:

Median valid-point deltas are.20--1.12mm; large maxima are not representative
of every track. This deliberately3.74m coordinate-origin shift is NOT the
actual millimetre-scale pose revision and does not reproduce the full trajectory.

Exported camera matrices, stereo baseline, observations and missing-right flags
were used in a separate NumPy homogeneous DLT/SVD calculation. It independently
matches ALL4056native classifications and3677returned-point comparisons to
6.34e-11m. This localizes the effect to the algebraic triangulation/rank/gating
procedure, not source-to-source belief transformation or a serialization glitch.

Explanation consistent with those calculations: homogeneous DLT minimizes an
algebraic error with a unit-norm homogeneous point. A translation of the world
changes that normalization for noisy, non-intersecting rays. The fixed absolute
singular-value rank threshold1 can also change its decision. Pure rotations
preserve the corresponding norm. There is no embedded reprojection refinement
in the saved setup. Exact noiseless observations do not expose the same effect.
This is a demonstrated numerical sensitivity/failed invariance property, NOT
proof of a newly introduced CBS code regression, wrong physical calibration,
wrong GLIM frame, or the origin of the actual CBS-ON instability.

4. WHAT THIS SAYS ABOUT THE THREE SUSPECTS
=========================================
Suspect1, visual support: real support loss is now established in the next
native linear system; most of this post-step loss is not stale cached status.
Additional initial-cache and world-origin sensitivity are documented. Their
causal importance for later shaking is untested.
Suspect2, equation correctness: remains open. Current/fresh equations can agree
while the nonlinear derivative or eliminated visual model is approximate.
Suspect3, nonlinear update behavior: remains open. No optimizer ablation or
extra iterations were run here, so no new conclusion about accepted steps.

Recommended NEXT isolated check: validate the native visual pose/point Jacobians
and landmark elimination at the SAME saved first-insertion states, with the SAME
triangulated point, valid set and noise, against independent numerical derivatives
and a direct joint-linear-system elimination. Distinguish that local model from
the operational retriangulate-and-reject cost. Include the frozen original-prior
chart as a separate check, not a simultaneous production fix. This is suspect2,
not another full run or loosened visual gate. Not launched in CP56.
