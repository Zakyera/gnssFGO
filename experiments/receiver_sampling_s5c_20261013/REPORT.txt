marginalization (this receiver never marginalizes). Rerun is not involved.
This audit establishes where time is spent; it does not establish the physical
or conditioning cause of every additional nonlinear refinement iteration.

5. One proposed fix — E2b exact shared endpoint evaluation reuse

The final active-factor inventory gives:
  Source         Edges    Endpoint uses    Unique endpoint times    Repeats
  GLIM            1476        2952                1478                 1474
  Kimera           725        1450                 726                  724
  Total           2201        4402                2204                 2198

Thus ~49.93% of references repeat a source endpoint already used by another
factor. At identical support Values, both need the same endpoint pose/Jacobians.
Current code computes them independently on whole-factor cache misses. This
static count is NOT an observed hit rate or measured speedup. E2 hits, traversal
order, changed Values and lookup overhead affect actual savings. Do not promise
2x whole-receiver acceleration.

The measured ranking reprioritizes S5a's motion V/W derivative proposal. It was
an unmeasured hypothesis, not a demonstrated dominant fix. E3a stays on hold.
E2b reuses the existing calculations instead of substituting new mathematics:

  a. Extend E2 exact-signature utilities with shared immutable endpoint pose
     and six Jacobian blocks. Keep the original calculation on every miss.
  b. Key includes support keys, physical time, dt/tau, Qc/interpolator flags and
     parameters, complete exact X/V/W representations/charts and output mode.
     Timestamp alone or approximate Values matching is insufficient. ANY
     relevant change invalidates reuse.
  c. Leave measurement mean, covariance, whitening and outer relative residual
     outside this cache. New revisions reuse endpoint work only if its inputs
     match; the new source measurement/noise still takes effect normally.
  d. Immutable returns, bounded lifetime/eviction and thread-safe access;
     candidate/recovery solvers must not corrupt each other. Exceptions and
     rollback cannot turn failed calculations into valid cached entries.
  e. Default-off private build. Test every key/parameter/one-bit Values change,
     cross-factor/revision sharing, candidate branches, rollback and concurrent
     access. Compare residual/Jacobian/Gaussian blocks to the original path.
  f. Exact saved-journal outputs, solver decisions/accounting and fresh
     stationarity checks BEFORE matched timing. Stop on mismatch. No model,
     derivative, tolerance, covariance or ordered-revision change. No live
     promotion from unit tests alone.

This follows the supervisor's useful reuse principle, but the reused object is
a receiver interpolation calculation, NOT GLIM GPU equations or a transplanted
source covariance. No source-estimator change is needed.

Even ideal halving of the ~33% interpolation path would remove only ~16–17%
of total CPU before lookup overhead/lost opportunities. This is illustrative,
not a prediction. QR/global traversal and more passes still grow. If measured
gain is insufficient, the structural target is publication's repeated global
evaluation/refinement. That requires a separately specified correctness-preserving
redesign, not larger queues or relaxed thresholds. Previously rejected E4
remains rejected; no fixed-lag change, version skipping or automatic next patch.
