and factor objects forever or holding a pose fixed.

3. EXACT CURRENT COMPATIBILITY OBSTACLES

The inherited retain code is present, but four distinct checks prevent simply
enabling it or substituting the general persistent mode:

  a. NativePriorRefresh.h:11..19 requires FL4M_RETIREMENT=remove.
  b. include/cbs/bpsam/bpsam.h:96..101 requires ActiveWindowTemporary,
     cached Gaussian factors and native Gauss-Newton (not persistent mode).
  c. incremental_fixed_lag_bpsam_smoother.h:236..243 requires every expiring
     peer slot to be scheduled for deletion before prior promotion.
  d. BpsamOnRefresh.inc:44..52 requires that a scheduled expired peer is already
     absent during the post-ordinary/post-refresh check, before marginalization.

OnRefresh.h:7..10 also requires CP-K9 enabled. Turning CP-K9 off is therefore
not a shortcut: it fails CP40's prerequisite and sacrifices the tested repair.
These are explicit supported-mode contracts, not evidence that the unchanged
OriginalChartPrior mathematics intrinsically forbids an inherited peer prior.
CP67 tested that representation at one boundary; repeated integration remains
unvalidated. No guard or implementation was changed in CP68.

Any private compatibility extension must replace remove-only assertions with
equally strict, mode-aware invariants, NOT simply delete checks:
  - Remove mode stays byte/numerically identical to the existing reference.
  - Retain mode verifies original slot/pointer/keys, an actually marginalizing
    endpoint, no scheduled deletion of that retained slot, and unchanged native
    staged/active residual bounds, including the retained old factor.
  - Exactly one ordinary solve and one CP40 refresh; no duplicate admission.
  - Immutable prior anchors/coefficients, owned-lock accounting, smart factors
    and full rollback remain intact; no resetting priors or stronger weights.
  - After marginalization: retained explicit peer consumed exactly once, no
    stale keys/slots/tracking, Schur parity and boundary continuity verified.
  - Current code commits retiring tracking before marginalizeLeaves and prunes
    after it. Test this actual order and whole-update rollback; do not assume
    that a missing tracking entry proves successful absorption.

not repair LOCAL provenance; it isolates a different, narrower question. The
saved CP66 ON stream already contains its original bidirectional history, which
would be held fixed in both arms, not called independent or feedback-free data.
No newly changed Kimera output would return to the sender in this diagnostic.
