Confirmed defect and correction
-------------------------------
The installed GTSAM LinearContainerFactor::error(Values) deliberately returns
zero when the container does not carry a linearization point. iSAM2 creates
such containers during marginalization. The prior is still present in the
optimizer's Gaussian system: this was an objective-DIAGNOSTIC omission.

The optional IncrementalFixedLagBpsamSmoother shadow audit now receives the
owning iSAM2 getLinearizationPoint() after the update and BEFORE marginalization.
For an unanchored container it evaluates:

  delta = Local(theta_of_this_graph, candidate_values)
  cost  = stored_Gaussian_factor.error(delta)

This includes the full dense quadratic and constant. Prior keys retain their
fixed linearization points; an arbitrary current estimate must never be
substituted for theta. An anchored container uses its OWN anchor. Ordinary
nonlinear factors retain their ordinary error evaluation. Before/after costs
use the SAME post-update graph, including newly inserted factors and excluding
removed ones, with new variables initialized as in the existing audit path.

Missing chart/value keys, wrong dimensions or types, invalid coordinates and
nonfinite costs return NaN through the audit adapter, invalidating the total
instead of silently contributing zero. Explicit type checking is required:
GTSAM GenericValue's local-coordinate cast is unchecked in this Release build.

The existing graph clone isolates diagnostic nonlinear-factor caches. No factor
is relinearized by this helper. No gradients are computed and no fixedVariables
are cleared. This is not a common-chart Jacobian/stationarity implementation.
