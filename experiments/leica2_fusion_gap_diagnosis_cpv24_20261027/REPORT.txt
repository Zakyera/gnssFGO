1. Bottom line

It is possible for this fusion to underperform its best source. However, that
is a limitation to isolate, not evidence that the current result is satisfactory.
For Leica-2 Velodyne the ORIGINAL fusion is between GLIM and Kimera, not worse
than both. The much poorer new result belongs to PURE INCREMENTAL CHAINING.
We must separate global trajectory accuracy from newest-point jitter.

Demonstrated: newest-state source availability/prediction and correction
stitching explain the local jitter mechanism; chaining drops useful corrections
and introduces additional drift. Not demonstrated: a single root cause or a
quantified allocation of the ORIGINAL roughly2m ATE between source conflict,
belief representation, motion model, covariance assumptions and solver policy.
No confirmed frame/interpolation/Jacobian bug in the previously tested cases.
Those checks are not a proof that all implementation issues are absent.

3. Why good native paths do not guarantee a better fused path

The receiver does NOT average the displayed green and orange absolute paths.
Receiver.h::dispatch inserts WnoaRelativeFactor(from,to,belief.mean,full C).
Each message describes a short relative motion, generally~0.2s, plus a6x6
LOCAL covariance; its MAIN mean can subsequently be revised. The fuser builds
its own100ms pose/velocity/angular-velocity states and7s WNOA graph from these
constraints. It does not have the full source graphs, visual/lidar raw factors,
their joint posterior, or the same native publication policy. In this frozen
receiver raw IMU observations provide a support clock only: there are no raw
IMU/GNSS measurement factors in the fusion graph.

Therefore neither exact reproduction of a native trajectory nor improvement
over the best source is guaranteed. Losing information when exporting local
constraints and fitting a different model is a plausible source of error;
its numerical contribution here has NOT yet been isolated. Small errors in
relative directions can accumulate into metres even when individual steps
look plausible. Best-source ATE is measured after the run, using a reference;
the receiver does not have that oracle during optimization.

4. Covariance is not a reliable oracle for which path is best

CP-V5 already measured retained source-relative errors at their own exact
physical endpoints, without a fitted global alignment. Matched first-belief
cohorts: median U=sqrt(trace(C_translation)) and RMS relative error, mm:

                 U median     Actual relative error RMS
GLIM OFF          2.085          28.638
Kimera OFF        1.560           6.640
GLIM ON           2.083          13.495
Kimera ON         2.371          13.664

U is a norm scale, NOT per-axis sigma or a95% bound. Median U versus RMS error
is an indicative scale mismatch, not a calibrated coverage/NEES certificate.
GLIM's reported LOCAL scale barely changes OFF->ON although its corrected
MAIN relative mean improves strongly. Both sources' actual errors exceed
these small conditional uncertainty scales. Covariance retains some health
ranking, but is not calibrated total-error knowledge.

The receiver trusts the FULL matrix, not its trace alone. Rotation, translation,
cross terms, time brackets and motion constraints affect the result. Do not
claim it simply always gives GLIM100x Kimera's weight; that is false here.
Within-belief dense covariance is preserved. Separate overlapping beliefs and
the two sources do not come with a joint inter-factor/source covariance. Shared
CPT7 and CBS exchange mean independence is not established. Treating these as
separate Gaussian factors is an approximation; this audit does not quantify
its contribution or prove it is the main cause. Stable-ID revisions REPLACE
existing factors; they are not accumulated duplicate observations.

The historical mean-only source-CBS alignment/covariance approximation remains
unchanged. It is a separate modelling concern, not a newly identified fusion
frame bug or an explanation for all OFF behaviour.

7. Why the new pure incremental path is worse

For publication k, G[k] is current graph pose and P[k] is the revised previous
pose from that SAME graph. Original history connected G[k-1] to G[k]. Chain
O[k]=O[k-1] inverse(P[k]) G[k] excludes the previous-point correction and uses
the accumulated odometry orientation. This avoids some jumps, but also drops
useful position/orientation corrections. It is not equivalent to Kimera's
native estimator just because both output policies are called incremental:
their underlying motion increments, state variables and evidence ages differ.

CP-V24 verifies an exact prism-point vector decomposition. Let f(T)=t+R*p_prism:
 d[k] = f(G[k])-f(P[k]); r[k] = f(P[k])-f(G[k-1]).
 Original increment = d[k]+r[k].
 Chain increment = R(O[k-1]) R(P[k])^T d[k].
 Chain-minus-graph displacement = sum(chain_increment-d) - sum(r).
All identities pass with max component error2.15e-14m across both full runs.

Previous-point corrections removed by chain, median/p95:
OFF2.276/7.462cm; ON1.788/4.163cm. These are from each consecutive publication,
not individual belief-update magnitudes. Some corrections alternate, others
accumulate. EOF chain/graph prism separation6.791893m OFF /15.583488m ON.
Accumulated rotation-frame mismatch is also present; it is between outputs,
not a reference orientation error. Exact vectors/series in results.json and
diagnostic_arrays.npz; their norms must not be treated as additive causal shares.

Consequently pure chaining is rejected as an accuracy fix. Continuous local
odometry can still be useful, but it needs an explicit corrected-global product
and correction/frame/covariance semantics. No publisher redesign is implemented.

8. What is ruled out, and what is not?

Already checked: first-published versus refined GLIM distinction; proper
matched masks; exact replay/output parity; full belief payload conservation;
stable-ID replacement rather than duplicate accumulation; sampled raw lidar
timestamp normalization and extrinsic chains; tested endpoint/Jacobian paths.
CP-V22A tested42024 Jacobian comparisons and1746 endpoint checks, with five
frozen linear systems per sensor case full rank and sub-mm remaining newest
linear correction. None is a proof of global nonlinear stationarity.

The initial pose anchor is already tight (sigma1e-5); stronger anchoring does
not address a shape error after rigid-aligned ATE. No evidence supports a
blanket arbitrary multiplier on the marginal prior. The WNOA motion prior is
a different constraint and has already been tested as a local-jitter tradeoff.

Not yet isolated: accuracy loss from each source's exported factor set versus
its native estimator, versus damage from combining sources; model/velocity
prediction contribution; correlation/covariance calibration contribution;
whether a broader solver-policy issue affects global drift. No claimed single
root cause for original ATE and no claim that the current fusion is optimal.

Use the existing Leica-2 CBS-OFF journal with the same original Qc,7s/100ms
supports, physical endpoints, arrival order, source means/C and expiry policy.
Run two fresh receiver-only controls: GLIM beliefs only and Kimera beliefs only.

roots; admit no GT-driven tuning. Score original absolute ONLINE and DELAYED

include prediction age, position and rotation RPE as well as ATE/path.

Interpretation:
- If single-source receiver already loses accuracy versus its native source,
  inspect belief representation, reconstruction and prediction before blaming
  competing sensor weights.
- If each source survives receiver reconstruction but BOTH degrades the better
  control, investigate conflict, covariance calibration/correlation and health
  selection with a clearly bounded follow-up.
- If ONLINE is poor but finalized source-time motion is good, prioritize the
  newest-state prediction/publication interface, not global trajectory smoothing.

Begin with OFF to isolate central reconstruction from source-CBS feedback.
