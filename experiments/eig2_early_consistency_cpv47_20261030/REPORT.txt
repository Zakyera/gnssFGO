CP-V47 -- EIG-2 CBS-ON early state / IMU consistency diagnosis
2026-10-30. Saved-data inspection complete; root cause NOT established.

DECISION
The saved data do not show a lost revised state, missing current-bias correction
inside GTSAM's IMU prediction, or incorrect IMU interval duration. They DO show
a mixed-reference initialization: the new pose's rotation uses raw preintegrated
rotation at an older integration bias, while the new velocity uses prediction
corrected to the latest backend bias. This is a concrete, narrowly testable lead,
not proof of the large CBS-ON oscillation's cause and not an implemented fix.

No source replay, new optimization, covariance investigation, weight change,
production modification, ATE/RPE scoring or promotion was performed. All values
below describe existing CP-V42/44 evidence, not a new full-sequence result.

3. WHY THE TWO BIAS REFERENCES DIFFER
At22--25, the newest PIM integration reference (biasHat) exactly matches the
latest published bias from k-2, rather than the revised latest state at k-1.
The earlier complete snapshot needed for this comparison at21 is absent.

The inspected native frontend lifecycle explains this ordering: it integrates
the interval, produces the keyframe/PIM and resets integration using the cached
bias before that keyframe is optimized by the backend. The later backend update
publishes a new bias. The next keyframe's raw integration therefore still has
the older reference. This is not evidence of a thread race or lost callback.

Native rotation-guided stereo uses raw deltaRij(), transformed into the camera
frame; its stereo pose retains the supplied rotation. The backend initializes
the pose from this stereo motion but initializes velocity using current-bias
IMU prediction. Code inspection and the five numerical rotation identities
agree on this mixed reference.

An older biasHat is NORMAL for a stored preintegration factor when correction
is applied. GTSAM predict()/ImuFactor do apply current-bias correction; the
audit confirms the predicted state is self-consistent (maximum norm1.182e-17).
The question is whether the frontend-guided pose seed becomes harmful under
large ON bias revisions, not whether GTSAM forgot its bias correction.

5. WHAT THIS DOES NOT YET ESTABLISH

  Early pose/cost chronology cannot prove the complete first causal chain.
- No raw IMU reintegration: accuracy of first-order bias correction under the
  larger bias changes has NOT been checked against re-integrated raw samples.
- No runtime frontend bias-reset receipt or complete early visual-inlier
  history (log_output=false). Native smart-factor observations saved at21--25
  do not establish exactly how frontend matching first changed at6.
- Current frontend/GTSAM source is hashed code-inspection evidence, separately
  from archived CP-V40/44 backend code and saved native checkpoint results. It
  is not asserted to be every archived compiler input of the original run.
- Altering only a backend seed would not reprocess frontend pixels, restore
  discarded observations or change their earlier rotation-guided selection.
- Previous CP-V43 frame/mean routing checks and CP-V46 exact-CBS-Jacobian
  ablation remain separate evidence. Neither is overwritten or relabelled.

6. NEXT BOUNDED TEST -- PROPOSED, NOT EXECUTED/AUTHORIZED HERE
Use these SAME five pre-ordinary saved checkpoints. Reproduce the unmodified
ordinary step, then change ONLY the newly initialized pose rotation to the
current-bias IMU-predicted rotation. Retain stereo translation, velocity/bias,
all old states, native visual measurements/factors, CBS, priors and weights.
Apply the same ordinary and configured refresh steps in both arms.

Measure actual old-window tilt/state differences, native IMU residuals, native
visual activity and objective changes. A lower initial IMU cost is expected by
construction and is NOT sufficient success. If subsequent large tilts remain
essentially unchanged, reject this backend-seed explanation and do not spend
a full run on it. Even a clear improvement would only justify a bounded live
validation; it would not prove the original first-admission cause is solved.

This rotation-only comparison is narrower than switching to a wholly IMU-based
pose guess, which would change translation too and confound the identified lead.
No full rerun, CBS weight change or covariance work is proposed at this stage.
