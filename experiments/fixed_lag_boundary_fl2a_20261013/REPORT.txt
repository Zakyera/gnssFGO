Why the old procedure failed
MarginalizeLeaves leaves joint Gaussian information tied to a fixed solver
linearization point. Standard iSAM2 removes these keys from relinearization,
even with forceFullSolve. A later relative-belief revision can move their
estimates. Ordinary refinement then need not minimize the exact retained
nonlinear objective tested by our publication gate. This was observed, not
inferred merely from ATE. It is not evidence that GTSAM's linear marginalization
is wrong or that its original approximate fixed-linearization method is invalid.

Candidate mathematical representation
For each saved joint marginal, store its original Gaussian (A,b and any constant),
original reference Values a, key ordering and ALL cross blocks. Its objective is

  f_m(x) = 0.5 || A Local(a,x) - b ||^2 + constant.

For an update dx in the CURRENT chart, its Jacobian is

  J_m(x) = A blockdiag( D Local(a_k,x_k)/D dx_k ).

Pose3 blocks use gtsam::traits<Pose3>::Local(a,x,none,Hcurrent). V/W vector blocks
use identity. The saved reference a NEVER changes while that marginal exists.
The original Gaussian error evaluates cost, preserving additive constants too.
Unsupported state types/nonfinite marginals fail; publication checks reject
nonfinite costs/gradients. There is no covariance scaling or new sensor belief.

The difference is where the frozen reference lives: explicitly inside the
marginal factor, rather than requiring the whole boundary variable's solver
linearization point to stay frozen. Ordinary active factors can be relinearized
while the old marginal information remains expressed in its original chart.
When a later retirement summarizes that marginal again, its correct current
chart Jacobian participates in the normal joint Gaussian elimination.

Bounded reconstruction and ownership
At each actual retirement the existing gnssFGO smoother eliminates old X/V/W.
New unanchored marginal containers become immutable AnchoredMarginal objects.
ONLY retained Values/factors are loaded into a fresh iSAM2, with null source
slots preserved during loading; normal slot reuse is enabled afterward.
No old trajectory states return, and no getFixedVariables mutation on an
existing tree occurs. The prohibited RebuildFullHistoryQR is never called.
The old and replacement marginal are never present together.

Source-owned active factor pointers/indices remain unchanged through rebuilding.
New receiver-owned marginals may fill empty slots; empty tail storage is trimmed.
Timestamp maps are untouched; no arrival-time timestamp refresh or suffix pin.
The transaction restores solver/tree/delta, maps, flags, marginal ownership,
rebuild/retirement counters and publication cursor after failure.

Strict publication
Threshold remains1e-5. At most20 publication-phase solver steps: pre-retirement
refinement, the existing ordering/retirement update, the bounded reload update,
and any post-retirement refinement are counted. Ordinary source/support admission
updates are separate, as before. This is not20 iterations independently per phase.
Cost must remain finite/nonincreasing within1e-12*(1+|cost|) rounding allowance.
No LM/recovery fallback is inserted into the candidate. LM is only an independent
test oracle, using a separately differentiated numeric-chart prior.

Engineering failure caught and corrected
Initial test_release1 passed the boundary/interpolation/accuracy-of-computation
gates but failed the prespecified slot-storage bound: high-water32 in30 linear
steps. marginalizeLeaves appends new marginals regardless of ordinary insertion
reuse. Preserving every empty tail slot therefore retained unbounded storage.
Correction moves ONLY newly generated receiver-owned marginal factors into
vacant lower slots and trims empty tail; source slots stay stable. The same
bound now passes with10. No test bound or mathematical criterion was relaxed.
This correction and retained initial failure are recorded in PROTOCOL.txt.
