DECISION
========
The CP-V37 current-state refresh now has a private incremental implementation
that passes focused synthetic mathematical, lifecycle and rollback tests.
It is NOT installed as a default, and no dataset has been replayed here.
There are no new EIG-2 RMSE/RPE/path-length results from this task.

This is the next engineering gate, not proof that the visible shaking is fixed.
CP-V37 demonstrated reduced IMU inconsistency on seven real saved windows;
CP-V38 tests whether that operation can be integrated without corrupting the
prior, covariance, native factors or fixed-lag bookkeeping. Full-sequence
accuracy, large-error robustness and throughput remain untested.

EXACT CANDIDATE
===============
Private root:
/home/yeranis/repos/V4RL/cbs_gtsam4.3/runs/kimera_off_incremental_refresh_cpv38_20261029
Derived from the existing CP-K9 private headers and unchanged libcbs.so.
No class data-layout, source-tree, installed-library or profile changes.

Explicit opt-in CPV38_OFF_REFRESH=1 requires CPK9_PRIOR_REFRESH=1,
FL4Q_ENABLE=0, FL4M_RETIREMENT=remove and native GN/active_window_temporary mode.
Absent/0 preserves baseline. Incoming belief bookkeeping rejects before solve.
The tests stage one synthetic incoming belief solely to check rejection; no
CBS-ON factor graph is optimized and no GLIM/receiver is run.

Each enabled fixed-lag update:
  1. Runs the ordinary update unchanged.
  2. Promotes native marginal containers using the existing CP-K9 immutable
     original-chart adapter and ownership/cache checks. All fixed locks must
     be accounted for; unknown/missing/corrupt ownership fails closed.
  3. Executes ONE additional empty native iSAM2 update with forced all-key
     relinearization/full back-substitution, in the same BPSAM object. The
     pinned GTSAM forceFullSolve path selects every nonfixed key; forcing a
     relinearization check alone would not unlock marginal-prior anchors.
  4. Performs ordinary native marginalization once, with unchanged timestamps
     and removal ordering. Newly formed native priors are handled next cycle.

The retained prior's function, original anchor, Gaussian and weight do not
change. Its Jacobian is expressed in the current tangent. This does NOT recover
the eliminated nonlinear measurements, reset the prior residual or strengthen
the prior. Native smart measurements, noise, validity/retriangulation rules,
IMU factors and biases are retained; no explicit landmarks or cache clearing.

One additional GN step per wrapper update is intentional. No LM, damping,
line search, convergence loop, new cost-acceptance criterion or core rebuild.
GTSAM can internally reeliminate the whole active graph because all keys are
affected; "incremental implementation" does not mean cheap partial updating.
Ordinary update counter/cadence is restored after the extra refresh. The wrapper
reports two steps; original ISAM2 result slot/unused-key bookkeeping is retained
for Kimera, so its original per-update diagnostic counts do not describe the
extra step. There is no second sensor frame, publication or timestamp insertion.

The enabled path gains a transaction/copy and mutable-smart-cache rollback.
The inherited comment about OFF having no transaction cost applies to default
OFF, not this opt-in. No performance claim is made for the new copying/refresh.
