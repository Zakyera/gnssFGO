experiments/e1b_local_update_batch_proposal_20261012) requires independent
ordinary/candidate LOCAL instances with independent mutable GPU state and
identical native update inputs, through marginalization, before interpreting

The existing IntegratedVGICPFactorGPU::clone() is NOT an exact state snapshot:
  src/gtsam_points/src/gtsam_points/factors/integrated_vgicp_factor_gpu.cpp:122-133

with null stream/temp-buffer arguments. It does not transfer current derivative
inlier state, cached linearization/error, linearization point, offloading/surface
validation settings or configured inlier-update thresholds.

initialization is at lines17-84. Mutable factor data are declared in
include/gtsam_points/factors/integrated_vgicp_factor_gpu.hpp:149 onward;

include/gtsam_points/factors/integrated_vgicp_derivatives.cuh:59 onward.
Paths above are under /home/yeranis/repos/V4RL/cbs_gtsam4.3/.

This is NOT evidence that clone() is broken for its intended fresh-factor use,
nor that batching changes the answer. It means that using it without additional
work would not meet our promised exact-state oracle contract. A shallow graph
or smoother copy also retains shared mutable GPU factors and is not independent.
