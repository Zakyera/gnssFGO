1. Scope and finding

The preceding candidate remains rejected and retained in
../e1_local_gpu_batching_20261011. Its full joint covariance error was
2.37628e-5, above its predeclared 1.10310e-8 bound. No gate was relaxed here.

The ordinary GPU batching hook does more than schedule kernels:
IntegratedVGICPFactorGPU::store_linearized() also sets evaluation_result and
calls derivatives->update_inliers(). Ordinary synchronous derivatives->linearize()
does neither. Using the native optimization hook unchanged was therefore NOT
a behavior-preserving replacement for the old LOCAL covariance preparation.
Inlier compaction can change subsequent floating-point reductions; covariance
inversion can amplify small differences. This is an implementation-equivalence
issue, not an uncertainty-calibration finding or evidence about CBS accuracy.

The new per-call compatibility path stores only the prepared linearization,
without compacting inliers or altering any prior error cache. The original failed
fixture and independent changing-Values histories now match exactly. This
supports the cache/inlier-semantics diagnosis; it is not a claim that every
possible real GPU graph is bit-identical or that all runtime delays are solved.

2. Implementation

gtsam_points:
- NonlinearFactorSetGPU::linearizePreservingSynchronousVGICP() validates unique
  exact IntegratedVGICPFactorGPU types, no pending linearization, and valid Pose3
  Values before work. It reuses the existing buffer/copy/kernel/synchronization
  loop through linearizeImpl(). No second kernel implementation was created.
- IntegratedVGICPFactorGPU::store_linearized_preserving_sync() only supplies the
  linearization cache. Default store_linearized() and native hook semantics stay
  unchanged. No object data members or virtual-method slots were added.

glim_ros1:
- linearizeCbsLocalGraphBatched() uses this per-call path on the backend thread.
  It does not change the global hook registry. GPU caches are consumed before
  CPU factors can throw. Missing GPU keys/types fail before preparation.
- Duplicate pointers, derived/other GPU factor types, or already-prepared native
  linearizations use ordinary whole-graph linearize(). CPU-only graphs use it
  without constructing a CUDA batch object. No concurrent use is supported.
- Pre-existing native error caches are preserved, not drained/replaced. A pending
  native linearization retains its old consumption behavior; this patch does not
  redesign that older API's cache contract.
- The existing glim_cbs_experimental_local_gpu_batching selector remains false
  by default. No launch or saved profile enables it.

No edits to sidecar optimization, LOCAL filtering, Schur covariance mathematics,
full dense source covariance, source mean, source CBS timing/policy, receiver,
WNOA, Qc, priors, scales, publication checks or event journals. No GLIM, Kimera,
gnssFGO, bag playback or sequence experiment ran. This is E1, not E1b or E2.
