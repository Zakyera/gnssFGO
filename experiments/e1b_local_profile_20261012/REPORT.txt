2. What is measured

One shared libe1b_profile.so owns thread-local context across the private DSOs.
Without CBS_E1B_PROFILE_PATH, logging/timing is disabled. Test-only in-memory
records can explicitly enable it. Output uses exclusive creation: no overwrite.
Opt-in sessions surround existing calls, not new solver/factor evaluations:

Context MAIN: native GLIM update_smoother body, including existing empty updates.
Context LOCAL: GlimCbsBridge::updateSidecar -> existing sidecar_->update.
Context COVARIANCE: outgoing-belief construction after endpoint request building.
Context REVISION: existing diagnostic revision-export block.

LOCAL scopes: fixed-lag preparation, BPSAM preparation/backup, BaseSAM::update,
post-update estimate/guards, marginalization and cleanup. Existing GTSAM timing
sites distinguish updateDelta, recalculate, batch/incremental recalculate,
affected-factor linearization and marginalizeLeaves. Recalculate is NOT a pure
QR timer: inner ordering/elimination are not separately resolved.

GPU-factor scopes distinguish error, linearize, cached-hit counts, synchronous
fallback and its existing warning/flush. No additional CUDA synchronization;
these are HOST elapsed durations, not GPU kernel timings. Warnings and shared
factor-cache consumption/inlier behavior are preserved.

Each stage stores calls/inclusive_ns/exclusive_ns/exception-unwind count.
Exclusive owner durations partition the session root exactly; root-exclusive
time represents unassigned work and instrumentation between scopes. Do not sum
nested inclusive durations. Metadata traversal has its own timer and records
active keys, allocated/non-null factor slots, retiring keys, variables
relinearized/re-eliminated and cliques from existing Values/results. Full factor
type histograms were not added; GPU calls are identified by their exact method.
Counts are sums within a session; repeated updates need that interpretation.

JSON schema1 context numbers:0 OTHER,1 MAIN,2 LOCAL,3 COVARIANCE,4 REVISION.
Metric array order is the enum in RuntimeProfile.h. One row per context/update,
not per factor, tagged by the available physical stamp. An empty-stamp main
update is tagged0 and cannot be guessed into a physical scan. Revision/context
rows are not estimator output timestamps or receipt/availability timestamps.
Legacy outer per-scan timing must still be retained for total-cost accounting.
Record serialization/fflush runs AFTER the measured root; thus root excludes
file-output cost. Error messages invalidate a future profile; never silently
accept a missing/truncated profile. I/O failure does not overwrite prior data.

estimate/covariance queries and equality comparison, not only smoother.update.

OFF before43.802us/update; ON49.639us; OFF after45.113us.
Increment against the two bracketing medians4.526–5.837us (~10–13%). Includes
timer collection,JSON serialization and fflush to local page cache, NOT fsync.
Native fixture logging is unchanged in both arms. Values are small-workload
observations, not a throughput guarantee or a confidence interval.

The first RAM overhead run overlapped the tail of the sanitizer build; the
subsequent I/O test ran after that build/tests completed. No representative
GLIM-factor workload overhead is measured yet. Real overhead depends on the
number of evaluated factors/warnings and filesystem/contention; cannot assume
either the2.3% fraction or5us increment for a real scan. Future capture needs
legacy outer timing, profile-row conservation and explicit perturbation limits.
