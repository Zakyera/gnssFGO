5. TIMESTAMPS: NO FOUND98ms BUG; A REAL14ms PHASE DIFFERENCE

Hesai point field is absolute seconds ('timestamp'). Velodyne uses signed
relative seconds ('time'), about-98--100ms to+1.306ms around its header.
The inspected GLIM normalizer moves frame time to the minimum point time and
subtracts that same minimum from each relative point time. Thus:
 (header+minimum)+(point_offset-minimum) = header+point_offset.
This preserves absolute point time; subtracting98ms from the frame stamp alone
must NOT be called a98ms synchronization bug.

Fresh raw-array check covers20scans per lidar in the first2s. Absolute times
are preserved within0.239microseconds. Native timestamps match all published
scans in that sample; six Hesai/seven Velodyne initial scans precede native
odometry startup and are explicitly unmatched, not treated as timing failures.
The existing Velodyne full-capture sensor audit separately checks every native
scan's normalized time and IMU coverage. Raw bags were sampled read-only; full
bag hashes were not repeated here. Preprocessor sorts selected points by time.
This is not an independent end-to-end numerical certification of deskew.
