SPX-3 STARTUP BELIEF TRACE — COMPLETED 2026-10-23
================================================

Conclusion
----------
The suspicious three Kimera startup edges are genuine source mean/uncertainty
mismatches, not a reporting mix-up. They start identically in CBS OFF and ON;
CBS subsequently IMPROVES all three means. Severe uncertainty/error mismatch
also exists in OFF. There is a concrete startup-assumption violation: Kimera
initializes with zero velocity and initialVelocitySigma=0.001 m/s, although
the reference shows motion at initialization. This is a strong, specific
mechanism to investigate before global covariance tuning, not a proven sole
cause or a proven coding defect.

Crucially, 0->1 and 1->2 were NEVER inserted into gnssFGO. All versions were
excluded because their start timestamps precede the receiver trajectory origin.
Only 2->3 entered, with one insertion and 24 replacements, then absorption of
revision 24 into the fixed-lag prior. These are not 25 concurrent factors.

This corrects a possible interpretation of the preceding ranking plot: the
two strongest confident outliers are real outgoing source beliefs, but not
direct constraints used by this receiver. They cannot have harmed fusion via
their own factors. Indirect effects through other source beliefs are not ruled
out. The remaining accepted edge is still much more confident than its error
against IE-TC warrants.

Scope
-----
Saved full SPX-3 CP-K26 OFF/ON captures only; 25 versions of each of three edges
per mode, 150 paired mean/covariance versions. No solver, source estimator,
replay, ROS or container was run. No settings, covariance, model, previous
results, input artifacts or source code were changed. Only this analysis
directory was created. These are relative-belief diagnostics, not new ATEs.

2. What actually happened at startup
-----------------------------------
Capture starts after the established 32 s bag offset. Kimera's first pose is
at capture+0.199708728 s, timestamp1730565903072597379ns. BOTH saved profiles:

    autoInitialize: 1
    initialVelocitySigma: 0.001

Both runtime logs explicitly report the stationary-initialization assumption,
and both first native odometry records contain zero velocity. The code path
selects initializeFromIMU, creates a zero velocity initial state and adds an
isotropic velocity prior with that sigma. This is Kimera source initialization,
NOT central-IMU fusion; the receiver remains no-central-IMU WNOA.

IE-TC symmetric position differences around that first pose give speed
0.39051 m/s over +/-20 ms and0.38909 m/s over +/-50 ms. The three subsequent
approximately200ms reference intervals have chord speeds:

Edge     Physical interval after capture start     Reference chord speed
0->1     0.199709--0.399707 s                       0.46349 m/s
1->2     0.399707--0.599705 s                       0.46771 m/s
2->3     0.599705--0.799704 s                       0.55790 m/s

Thus a stationary/near-zero-velocity initialization assumption is inconsistent
with the observed physical motion at this crop boundary. A wrong tight prior
can bias motion estimates while the conditional graph covariance shrinks as
more factors accumulate. LOCAL covariance still includes local initialization
and model assumptions; excluding external factors is not protection against
a wrong local prior. This explains a plausible mechanism, not its quantitative
share of the error. No prior ablation has been run and none is claimed.

All selected OFF/ON means AND covariances are exactly identical through source
update4. The first incoming G2K alignment is update5, source edge1->3 aligned
onto Kimera3->4. All three tracked edges first differ at that same update:
0->1rev4,1->2rev3,2->3rev2. The startup errors therefore precede CBS injection.

6. Interpretation and bounded next question
-------------------------------------------
Established: real startup error, correctly transported covariance, OFF/ON
identity before CBS, subsequent improvement from the ON run, severe remaining
source uncertainty mismatch, and exact exclusion/replacement/absorption.

Strong specific hypothesis: a moving crop start is incompatible with the
stationary zero-velocity initializer and its tight prior. This is a more
concrete explanation to test than blaming CBS covariance shrink alone or
inventing a universal scale multiplier from these three points.

Not established: the sole cause of the source bias; the proportion attributable
to initial velocity vs orientation/bias/model/visual constraints; the exact
change in fused trajectory caused by2->3; or universal behavior across missions.
These three edges were selected because they were outliers, not as a random
calibration population.

Recommended next decision (NOT executed): treat startup validity as a separate
precondition before covariance tuning. If a further mechanism test is wanted,
predeclare one isolated initialization comparison, preserving the production
checkpoint and evaluating downstream covariance/error after a physically
valid startup. Do not initialize with evaluation GT, silently trim the saved
ATEs, or globally weaken Kimera based on these startup-only observations.
