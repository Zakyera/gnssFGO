PROPOSED INTEGRATION — NARROW, EXPLICIT, DEFAULT DISABLED
======================================================
Use the existing NonlinearFactorSetGPU compatibility backend at MAIN's existing
ISAM2Ext linearization sites. Add a narrow opt-in MAIN dispatch/adapter, not a
second optimizer, new CUDA kernels or a process-wide ordinary-hook enable.
Choose the smallest instance-scoped or explicitly scoped integration after
checking the archived implementation; do not apply it to every smoother.

Required call-site inventory in gtsam_points/optimizers/isam2_ext.cpp:
  update(): new factors;
  recalculateBatch(): full selected graph;
  relinearizeAffectedFactors(): exact uncached affected subset;
  marginalizeLeaves(): the factors the existing code actually linearizes.
Keep factor selection, theta, cacheLinearizedFactors decisions and elimination
unchanged. Never freshly linearize a factor whose existing Gaussian is reused.
Keep Gaussian factors in the ORIGINAL synchronous ordering and factor slots.
The stock hook appends GPU results after CPU results in some loops; do not
silently inherit that ordering change or misassociate results with indices.
Retain null slots, key order, removed/replaced factors and slot-reuse semantics.

Prepare only real derivative requests, consume each prepared result once at the
same Values, and finish the operation before returning to the solver. No reuse
across theta epochs, residual queries, replacement, retirement or rollback.
Keep synchronous inlier selection/reset rules and do NOT call the ordinary
store_linearized() compaction/update_inliers or overwrite evaluation_result.
Do not treat "same number of inliers" as proof of identical correspondences:
check indices, anchor, buffers and relevant settings.

Error-only requests retain the original synchronous behavior. Some native hook
call sites linearize before evaluating error; do not introduce those extra
state changes via a global factory registration. The frozen odometry profile
uses Gauss-Newton (use_isam2_dogleg=false); evaluateNonlinearError defaults false
in the inspected construction. Assert effective parameters in the candidate.
Unsupported optimizer/error modes must retain the reference route or fail
admission explicitly, NOT change settings to make a test pass.

Only exact supported VGICP types enter the compatibility backend. Preflight
the whole request for aliases, pending caches, types and required Values before
mutation. Unsupported batches use the original synchronous route with a counted
reason. Preserve aliases; never batch a shared mutable factor twice. On a
catchable failure, leave no newly prepared cache for a later Values epoch.
Do not clear a pre-existing cache or conceal fatal CUDA failures with retries.
Use the existing serialized backend ownership; no new host concurrency.

Prove effective activation through actual loaded paths/hashes and counters:
eligible/prepared/consumed factors, synchronous fallbacks by reason, batch sizes.
An unconditional startup message or build flag is not an activation check.
If registration is used, it must precede MAIN construction, occur exactly once,
and avoid also enabling the ordinary hook or affecting an unrelated smoother.
