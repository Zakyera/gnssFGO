Receiver implementation
One active map entry owns one factor pointer/slot and latest admitted payload
for stable(source,session,from_index,to_index). source/session count is not fixed.
Endpoint stamps are immutable per ID. Exact ns bracket arithmetic maps arbitrary
physical endpoints onto independent supports, including shared brackets.
One arrival version is one ordinary forced-relinearization iSAM2 replacement,
matching E2b ReplaceFactor. It removes the old slot then inserts one revised
mean AND complete covariance. No source averaging, row selection or coalescing.

Pending versions retain arrival order individually until their right support
exists. Later/lower revisions are not silently collapsed. Existing1e-12 duplicate
payload tolerance is retained; conflicts and changed endpoint timestamps fail.
Before-X0 exclusions and unavailable-at-EOF right brackets are distinct from
lag-induced failures. Source sessions can change without colliding with old IDs.
Code review caught and corrected validation ordering in the initial candidate:
endpoint identity is now checked BEFORE startup exclusion/pending classification,
also against still-pending IDs. New negative tests prevent a malformed changed
start timestamp from being silently reclassified as before-initialization.
Normal synthetic archive products must remain unchanged; no tolerance changed.

At each support boundary: add support/WNOA, dispatch eligible pending versions,
refine, capture validated outgoing states, retire X/V/W by physical tick,
translate/reload anchored marginal using FL2a, refine/check, reconcile consumed
source slots, then commit. Strict cutoff retains equality. Source timestamps are
never refreshed by arrival/revision. No suffix pinning or old-state resurrection.
The20-step budget includes refinement, ordering/retirement and active-only reload;
normalized gradient threshold stays1e-5. The prior is evaluated with its original
chart/cross terms. No full-history fallback after retirement.

Absorbed IDs are written into the archive, removed from the active map, and
cannot be replaced through a recycled slot. Any later version of an absorbed
ID fails closed, including a changed endpoint payload. A new unknown ID whose
old bracket is gone also fails. Pending intervals that would cross retirement
stop BEFORE information is lost rather than pinning an ever-growing window.

Transaction and storage
Solver-mutating events operate on a staged active-state copy: iSAM2, marginal
anchors, physical clock/maps, pending ownership, IDs, counters and cursor.
Failure before commit leaves the original receiver and published files unchanged.
Raw timestamp samples emitting no support only validate/commit a scalar clock
copy: no graph snapshot at raw IMU frequency. Products must exactly match the
earlier always-staged implementation; this is not a measured speed claim.

Archive: create-new single-writer output root; immutable per-event commit bundles
and direct on-disk absorbed-ID index. Output becomes visible at a directory
rename; all exception-prone solver/check/output staging work occurs first. The
receiver pointer swap afterward is noexcept. Failed staging removes only its own
uncommitted generated files. Existing roots are refused; there is no crash-resume
or fsync/power-loss durability claim. A disconnected stream withoutE never
receives a successful finalization marker.

No all-history Values, source ID map or trajectory vector is copied/scanned in
the active estimator. Finalized history and absorption markers grow ON DISK.
Pending storage depends on arrivals/lateness; arbitrary unbounded rates/stalls
are not supported by any bounded-memory claim. Disk per-event overhead has NOT
been benchmarked and must be included in FL3 whole-service timing.

The optional shared E2b endpoint cache is explicitly disabled via withCache(nullptr)
in this first correctness adapter. Factors keep only their own current endpoints;
their payload is released on absorption. This avoids shared mutable cache state
across rollback; the frozen E2b cache/full-history executable are untouched.
No endpoint-cache acceleration is claimed here. Re-enabling shared reuse requires
separate isolation/rollback checks, not a hidden flag change in a real run.

Output meaning
online = immutable current-support publications at their real availability time.
finalized = outgoing last validated state at retirement + remaining EOF window.
drain = final current state after arrivals following the last support publication.
Finalized is NOT a globally retrospectively reoptimized trajectory and NOT live.
export_archive.py writes separate online.tum/finalized.tum and fullX/V/W state
tables only from a complete committed archive. It does not align, score or rerun
anything; incomplete archives are refused. Original native GLIM/Kimera paths
remain distinct and were neither used as this test's output nor modified.
