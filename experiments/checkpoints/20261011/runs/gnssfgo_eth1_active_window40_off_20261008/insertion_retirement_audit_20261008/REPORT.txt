ETH1 temporary-CBS 40 s: GLIM -> Kimera insertion / retirement diagnosis
======================================================================
2026-10-08. Retained-data analysis only. No estimator execution or changes.

Conclusion
----------
The earliest native Kimera OFF/ON divergence is at backend update 4, physical
time 3.951896 s, the update containing the first accepted GLIM factor. All
retained pre-insertion smoother poses are identical between OFF and ON.
The first marginalization is at 8.351873 s; the first CBS factor retirement is
at 8.751871 s. Neither can explain the onset at 3.951896 s.

On the first factor's exact receiver interval, GLIM's transmitted rotation is
less accurate against IE-TC than Kimera's pre-update rotation. After the update,
Kimera agrees more closely with GLIM but has a larger rotation error against
the reference. The targeted historical edge's translation nevertheless improves.
The newly published native increment gets worse in BOTH translation and rotation.

There is also an approximately 20 ms physical endpoint mismatch in all 175
accepted factors: the classic receiver matches nearby Kimera timestamps and
uses the sender transform unchanged. This passes the configured 50 ms tolerance,
but does not make the physical intervals identical. Comparing against the actual
receiver interval substantially increases the aggregate rotational discrepancy.

These findings identify concrete mechanisms worth separating; they do NOT prove
that one factor or the timing mismatch accounts for the entire ATE difference.
Many insertions improve their targeted historical edges. No isolated within-run
counterfactual removing only CBS was recorded. This audit does not diagnose the
reverse Kimera -> GLIM direction or claim why GLIM's global ATE improves.

6. Native output semantics and first retirement
-----------------------------------------------
Both runs use --no_incremental_pose=false. Kimera's original ROS odometry
appends the latest relative increment from the current optimized snapshot:

  O_u = O_(u-1) * inverse(X_(u-1)^u) * X_u^u.

O is the published increment-chain trajectory; X is the current smoother state.
Earlier O outputs are not retrospectively rewritten when older X states change.
The logged same-snapshot increments reproduce native increments with maximum
SE(3) log coordinate discrepancy 1.695936e-11. This is a checked code/output
relationship, not a substitution of a reconstructed path for native odometry.
It explains why correcting x2 -> x3 need not repair the already-published past
while the same optimization also changes the newly appended x3 -> x4.
It does not by itself quantify its share of the accumulated ATE loss.

At first retirement u28, x2 -> x3 is removed; x2 is no longer available in the
post-update snapshot. We therefore compare only 24 adjacent edges present in
BOTH snapshots, not a stale retired state. ON translation RMS changes
4.591111 -> 5.330731 mm; rotation RMS changes 0.163579 -> 0.162505 degrees.
The corresponding OFF values are 1.513420 -> 1.492053 mm and
0.156748 -> 0.156689 degrees. A new CBS factor and native visual/IMU factors
also enter this update. These numbers cannot isolate a removal-only effect.
The onset predates retirement; later retirement effects remain unquantified.

8. Validation, artifacts and limits
-----------------------------------
extract.py reads the retained ROS bag, not a regenerated estimator product.
It extracted 389 actual GLIM wire beliefs, 184 native Kimera ROS output stamps,
and 8021 bracketing IE-TC reference poses. Each of 175 accepted mappings has one
matching revision-0 wire mean and its full 36-entry covariance.

analyze.py and verify_trace.py reuse retained project SE(3) and log parsers.
  - Wire covariance vs logged factor matrix: maximum difference <1e-15.
  - Reconstructed pre residual checks: maximum discrepancy 2.467124e-14.
  - Reconstructed post residual checks: maximum discrepancy 2.541023e-14.
  - All accepted wire arrivals precede the corresponding output record time.
  - Pre-first-insertion snapshot matrices exactly equal OFF/ON.
  - Expmap/Logmap diagnostic roundtrip test passes.
  - All audited input hashes remain unchanged.

Files in this directory:
  summary.json                     Aggregate results and input SHA-256.
  trace_validation.json            Independent timeline/identity consistency.
  extraction_provenance.json       ROS bag and original reference SHA-256.
  accepted_insertions.csv          Every accepted factor, mapping and errors.
  native_relative_intervals.csv    Every normal native output increment.
  native_off_on_pose_differences.csv  First divergence and all native differences.
  retirement_surviving_edges.csv   Every retirement update's surviving edges.
  early_event_trace.json           Early exact matrices and full covariances.
  wire_beliefs.json / reference.npz  Retained-data extraction for reproducibility.

The same backend update includes native visual/IMU factors, nonlinear solving,
and this mode's relinearization behavior. The logs do not furnish an isolated
CBS-factor-only causal intervention. Reference uncertainty and shared CPT7
information also limit statistical calibration claims. No source settings,
covariance, timing, fusion, or historical artifacts were modified. No source or
fusion run was launched. New files are confined to this diagnosis directory.

Bottom line: insertion-time local rotation disagreement is already present
before any marginalization/retirement; approximate endpoint matching adds a
measurable interval inconsistency; native increment output and historical-edge
correction are not interchangeable. Do not start covariance tuning from this
evidence or claim that the whole OFF/ON accuracy gap is now explained.
