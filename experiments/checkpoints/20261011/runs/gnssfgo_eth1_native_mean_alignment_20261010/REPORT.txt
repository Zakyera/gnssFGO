1. Scope and unchanged settings
------------------------------
Only the received relative MEAN is adapted to the actual receiver endpoint
times. For sender [a,b], receiver [c,d]:

    Z_receiver = U(c,a) * Z_sender * U(b,d).

U is a nominal IMU bridge, using the receiver's existing native integrator,
available IMU history, and pre-update active pose/velocity/bias. No reference
trajectory or final/future smoother pose supplies an adapter state.

No covariance formula, scale, robust kernel, source weighting or gating was
added/changed. Every incoming 6x6 covariance is passed unchanged through the
new adapter. Kimera's 20-factor native gate verifies all 36 entries exactly
against the wire and actual BPSAM factor construction. The subsequent recovered
40 s bidirectional run passes all 181 GLIM and 179 Kimera runtime covariance
checks. Section 9 retains the earlier short-run exact-repeat failure; sections
10-11 document the authorized numerical criterion and successful final replay.

Important statistical limitation: keeping covariance frozen is intentional,
as requested. The adapter does not transform/add uncertainty for the bridge
or account for bridge/source correlations. This is a mean-only correction,
not a claim of a fully calibrated new measurement distribution. New source
estimates can naturally change later exported marginals; that is not covariance
scaling and does not imply that ON and OFF payloads will have identical values.

Both new switches default FALSE:
  Kimera gflag: cbs_experimental_native_imu_mean_alignment
  GLIM ROS parameter: glim_cbs_experimental_native_imu_mean_alignment

Shared production launch files/defaults are unchanged. Private launch copies
enable the switches. The private runner explicitly selects the new Kimera
build library; the installed devel Kimera core library was not replaced.
GLIM ROS library/node and dependent Kimera ROS targets were rebuilt.

The ETH1 profile remains front stereo/shared CPT7, Kimera 25 states, GLIM Hesai
5-second lag, classic source CBS, 0.20-second horizon, one pair/update,
schur_relative_between, scales 1. Both receivers retain the selected historical

Native IMU conventions are preserved: Kimera's exact current frontend packet
intervals (including interpolated image boundaries), and GLIM's existing native
integration. No ALL_RIGHT override was newly applied to Kimera.

The central receiver remains no-central-IMU WNOA, 100 ms independent clock,

2. Native implementation
------------------------
Kimera:
  src/Kimera-VIO/include/kimera-vio/imu-frontend/CbsNativeImuMeanBridge.h
  Pipeline::spinOnce caches the actual frontend IMU packet via VioBackendModule.
  VioBackend::cacheCbsNativeImuPacket is a no-op with the flag disabled.
  VioBackend.cpp's received-belief path uses exact receiver nanosecond timestamps,
  selects active pre-update x/v/b anchors, clips fractional IMU intervals and
  calls native ImuFrontend preintegration/predict. Missing history cannot fall
  back to an unaligned measurement; it follows the existing retry mechanism.
  KIMERA_CBS_MEAN_ALIGNMENT_ROW retains source/receiver timestamps and raw/aligned
  means, with the unchanged covariance, for validation.

GLIM:
  src/glim_ros1/include/glim_ros/cbs_native_imu_mean_bridge.hpp
  GlimROS::insert_imu caches the same time-shifted/scaled native sample passed
  to odometry. GlimCbsBridge::buildExternalFactor adapts the mean using active
  native x/v/b and native IMUIntegration. Missing history rejects construction;
  it never silently inserts a raw mean. No GLIM retry policy was added.

The GLIM gate exposed an implementation mistake in the first adapter version:
latestPoseStamp() was the previous completed scan, and even the newest scan
pose is stamped at scan START. A camera endpoint later than that pose can
already be available in the received IMU data. The final implementation uses
native_imu_mean_bridge_->availableUntil(), bounded by actual received samples.
It still rejects endpoints beyond that bound and never extrapolates the last
IMU sample. Active optimized anchors remain pre-update. The final correction
has focused unit validation and passes the recovered native GPU gates,
including the 40 s case documented in section 11.
