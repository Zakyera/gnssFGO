CP-V97 — EARLY KIMERA COVARIANCE DIFFERENCE, SAVED-DATA DIAGNOSIS
2026-11-03. No new estimator run. Whole-run GLIM ATE cause remains open.

Conclusion
The large early difference is already present in Kimera's native LOCAL covariance,
before Alpha->CPT7 conversion and insertion into GLIM. An independent saved-matrix
calculation reproduces it. At the same event, Kimera's visual-factor population
and effective visual information differ substantially. This is not evidence of
an arbitrary insertion multiplier or an inversion failure. It also precedes the
first marginalization, so absorbed peer information in a marginal prior cannot
explain this INITIAL change. That does not exclude later persistent feedback.

LOCAL versus all-factor covariance
The detailed independent graph audit excludes all explicit peer factors, then
recomputes marginals at the current MAIN estimates. Its full6x6 LOCAL result is
exactly equal to the first exported native matrix at both audited events in both
runs. It is NOT the smaller all-factor covariance being mislabeled as LOCAL.
No marginal prior exists yet at the7.9s event. However, the CURRENT STATES used
to linearize native nonlinear factors already incorporate peer corrections.
LOCAL does not mean a separately optimized CBS-OFF solution.

Numerical checks
Independent NumPy direct propagation H * inverse(joint_information) * H^T
reproduces the audited covariance; relative error at the7.9s LOCAL event is
2.12e-14 old and3.48e-14 new. Both are SPD; no jitter is used. Across all36755
logged covariance queries in each run, all statuses are ok, all modes are
schur_relative_between, all queries use tmp_marginals, and jitter count is zero.
Maximum logged Schur/direct difference divided by covariance trace is2.05e-10
old and1.65e-10 new. This is numerical consistency, not uncertainty calibration,
nonlinear stationarity, or evidence that the native factors are all healthy.

Visual mechanism: observed versus inferred
Observed: changed numbers of smart factors and changed pose-key support multisets;
the endpoint contribution count changes20->70 despite fewer touching factors.
The saved BackendParams use Hessian mode, zero-on-degeneracy,10m landmark-distance
threshold,3px dynamic outlier threshold,0.001 retriangulation threshold and
smartNoiseSigma3. These settings are unchanged. Native smart factors can give
zero information when triangulation/validity checks fail, and relinearization
at a different state can change that. The exact reasons for these particular
zero/nonzero outcomes were NOT logged; do not call all zero rows outliers.

Code shows a plausible second pathway: backend updateStates sends its latest
IMU bias to the frontend; frontend preintegrated rotation is used for tracking
and mono/stereo geometric outlier rejection, and integration resets with the
cached latest bias. Thus identical images/IMU samples do not by themselves force
identical accepted visual factors when the estimated biases/timing differ.
The pinned private backend confirms the callback. Current frontend source shows
the consuming path but is not individually pinned in this experiment's manifest.
We do NOT have the actual synchronized bias-used trace or saved complete feature
measurements/landmark identities to prove this pathway caused the observed change.

Do not equate smaller covariance with a worse belief
At this event CP96 found raw relative translation error versus IE-TC decreased
14.30->6.95mm; after native interval alignment for insertion,14.85->10.52mm.
At5.70s it also improved. The confidence changed more than these individual
errors, but one residual cannot calibrate a6x6 covariance. IE-TC shares CPT7
with GLIM and is not independent prism ground truth. The aggregate GLIM ATE
regression .041500->.053058m is real on the common mask, but its causal connection
to these early factors is unproven; CP96 also found improved short-baseline RPE.

source_review.json records this clarification without overwriting analysis.json.

Boundary and recommended next test
We have localized the initial covariance difference to native active visual
information, not a transport bug or marginalized prior. We have not isolated
changed measurements versus changed linearization/triangulation, and have not
proved which event causes the later ATE difference. Existing saved logs do not
contain the complete native graph needed for that counterfactual.
The next discriminating experiment would be a SHORT instrumented capture through
about12s, saving native smart-factor measurements/IDs, triangulation status,
linearization poses and frontend bias-used timestamps. Then use the saved graph
to vary factor contents and linearization state separately. Do not change weights
or launch another full sequence just to answer this question. Nothing launched.
