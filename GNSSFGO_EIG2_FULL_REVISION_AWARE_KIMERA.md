## Which native Kimera trajectory?

The historical 1.309657 m EIG-2 native Kimera ATE came from recorded `/kimera_vio_ros/odometry`, exported as `kimera_odometry.csv`, **not** retired smoother states. That ROS topic normally reports the increment-composed online pose (`W_Pose_B_lkf_from_increments_`); outgoing CBS beliefs are computed from the fixed-lag smoother. The new source run's 1,523-row `kimera_odometry.csv` is byte-identical to the retained older CBS-OFF run (SHA-256 `369277944988416ed6728bdb37799afcfa34858a51e30718ace891e273b62e90`). Thus the old native result's trajectory identity is verified. Its 1.309657 m score used the earlier full source evaluation window; it must **not** be compared as if it used the 947-pose common mask below. No separate Kimera shutdown trajectory was retained in either run. We distinguish:

- **Native online:** the recorded increment-composed ROS odometry, i.e. the source product previously called “native Kimera.”
- **Native smoother first:** first logged smoother pose per retired source index.
- **Native matured:** each pose's last active smoother estimate immediately before fixed-lag retirement. The final 26 belief IDs with an active endpoint are right-censored, not labeled finalized.

## Diagnostic revisions and source topology

`KIMERA_CBS_REVISION_AUDIT=1` enables a read-only diagnostic path in [VioBackend.cpp](/home/yeranis/repos/V4RL/cbs_gtsam4.3/src/Kimera-VIO/src/backend/VioBackend.cpp) and [VioBackend.h](/home/yeranis/repos/V4RL/cbs_gtsam4.3/src/Kimera-VIO/include/kimera-vio/backend/VioBackend.h). The normal first-publication ROS belief is assembled before the audit query. For each stable `(source,from_index,to_index)` ID, the log retains physical endpoint stamps, publication/update ID, both endpoint poses, relative mean, all 36 covariance values, subsequent jointly active snapshots, and final active poses upon retirement. The existing `getOdometryBeliefs()` computes the two poses, joint marginal, relative mean and covariance from one smoother snapshot; the exporter rejects missing, nonfinite, nonsymmetric or non-PD covariance. The new diagnostic does not change Kimera's outgoing first-publication messages.

The [exporter](tools/eig2_kimera_revision_export.py) uses the actual recorded CBS belief as revision 0, matching its mean **and all 36 covariance entries** to the diagnostic snapshot within `1e-11`. For later versions it uses the recorded ROS odometry time of that same backend update as a conservative availability proxy; the source had computed the version by then. These are **offline diagnostic revisions**, not an existing CBS revision wire protocol. Stable IDs and increasing revisions are carried in [first.csv](/home/yeranis/repos/V4RL/cbs_gtsam4.3/runs/_eig2_kimera_full_revision_20260924/full305/revision_products/first.csv), [revisions.csv](/home/yeranis/repos/V4RL/cbs_gtsam4.3/runs/_eig2_kimera_full_revision_20260924/full305/revision_products/revisions.csv), [last_revision.csv](/home/yeranis/repos/V4RL/cbs_gtsam4.3/runs/_eig2_kimera_full_revision_20260924/full305/revision_products/last_revision.csv), and [finalized.csv](/home/yeranis/repos/V4RL/cbs_gtsam4.3/runs/_eig2_kimera_full_revision_20260924/full305/revision_products/finalized.csv).

## Receiver cases and evaluation convention

K0 uses only actual first publications. K1 causally inserts revision 0 and atomically removes/replaces its same-ID factor when each newer complete mean-plus-native-covariance version becomes available. K1-online is the as-played current estimate; K1-final is the final graph after later revisions. K2 inserts each last **jointly valid** source version at physical time as a noncausal oracle. K3 uses individually retired endpoint poses for the mean and K2's latest *genuinely computed* joint covariance; it is a noncausal control, **not** a claimed same-snapshot finalized belief.

An isolated [pose-only graph](tools/eig2_kimera_pose_only_receiver.cpp) uses native source gauge priors at the **two actual component roots** and the exported factors. It adds no artificial connection between components. The full receiver uses the unchanged Combined IMU, WNOJ, four priors, ALL_RIGHT CPT7 handling, 2,992 support states, iSAM2, and native dense covariance. The only full-receiver change is opt-in Kimera-only routing into its existing revision ledger plus diagnostic endpoint indexing for double-interpolated factors; factor mathematics is unchanged. GLIM's frozen CSV supplies support-grid **timestamps only**, not measurements. That grid begins after the small component, so each full case accepts exactly the **1,492 main-chain IDs**, skips three unsupported early edges, and accepts **zero GLIM factors**. All 1,492 accepted factors interpolate both physical endpoints. K1 receives 37,375 version rows, inserts 37,300 supported rows (including 1,492 first insertions), performs 35,808 replacements, and skips 75 versions of the three unsupported early IDs. There are no duplicate or stale revisions. This is a clear coverage limitation, not an invented bridge or topology repair.

For scoring only, every source/pose-only/full trajectory is sampled at the same 1,493 physical Kimera main-chain timestamps spanning 298.398 s. No factor or estimator state is interpolated for this purpose. The unchanged AP20-prism evaluator uses CPT7 body frame, lever arm and no-scale SE(3) Kabsch; the existing IE-TC 1 s RPE evaluator is reused. ## Decision and limits

**Kimera does exhibit fixed-lag endpoint revision, but its first-published belief chain already preserves the published online odometry. Revision-aware replacement is therefore *not required* to reproduce the previously scored native Kimera online trajectory, unlike the GLIM case.** If the intended downstream product is the evolving *smoother* snapshot, revisions are semantically required: K1 nearly equals K2, and both move decisively away from K0 toward the much worse matured source behavior on this run. They do **not** improve AP20 ATE here. This is a source-product distinction, not evidence that revision mathematics is wrong, nor a recommendation to alter fusion weighting. The native online path and matured smoother path are genuinely different products; K0 versus K1 also changes native covariance as the source itself does, so the receiver difference is not attributed solely to means. The GNSS/IMU/WNOJ graph is not expected to have exactly the same error as either source trajectory.

The primary limits are the three early unsupported IDs, 26 right-censored tail IDs, partial prism coverage, conservative odometry-record availability proxy for diagnostic revisions, and the absence of a live CBS revision protocol or shutdown trajectory. No GLIM+Kimera, CBS-ON, GNSS-factor, covariance scaling, health weighting, topology change, or revision throttling run was performed.
