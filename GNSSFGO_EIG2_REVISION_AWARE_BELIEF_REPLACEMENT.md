# EIG-2 GLIM revision-aware belief replacement (bounded diagnostic)

Date: 2026-09-23. Scope: **CBS-OFF GLIM only**, the same 0.20 s `i→i+2` source topology, and the first 592 fully retired source poses (59.100 s) from a new 65 s EIG-2 source execution. There is no Kimera, GNSS, CBS-ON, covariance scaling, GP/IMU retuning, or topology change. This follows the [publication-revision/topology audit](GNSSFGO_EIG2_GLIM_BELIEF_REVISION_TOPOLOGY_AUDIT.md). All four receiver cases below use the **same new source execution**; they are not mixed with the earlier run's saved edges.

## Result and central comparison

**Replacing** the active GLIM factor when a newer mean-and-full-covariance revision arrives removes most of the first-publication loss in this bounded window. The causal R1 final graph reaches 0.011416 m ATE versus R0's 0.052062 m. R1 is within 0.000176 m ATE and 0.85 mm raw-trajectory RMS of the noncausal last-revision oracle R2. Its online, as-published current-state trajectory is less accurate than its retrospectively revised final graph, so the final score must not be mistaken for zero-latency online accuracy.

The pose-only graph has **two disconnected parity chains**; its values below are separate even/odd ATEs with separate diagnostic gauges, not a falsely combined full-path ATE. The full receiver's existing Combined IMU + WNOJ factors connect its support states.

## Source revision stream and covariance provenance

The source run is [here](/home/yeranis/repos/V4RL/cbs_gtsam4.3/runs/_eig2_glim_full_revision_20260923). It reuses the retained EIG-2 Hesai/CPT7 GLIM-only launch, `observe_only`, direct smoother marginals, `schur_relative_between`, 5 s source lag, 0.20 s horizon, **one published pair per update**, and the same 5.7–70.7 s bag window at 0.10× playback. The existing endpoint audit flag is false by default and enabled only in this diagnostic run. GLIM's smoother, factors, LiDAR/IMU settings, and estimation mathematics were untouched. There were 641 first-publication beliefs, zero duplicate selected publications, 641 bag/log first means and every 6×6 covariance entry agreeing to `1e-12`, and zero covariance-computation error rows.

The diagnostic-only change in [GLIM's bridge](/home/yeranis/repos/V4RL/cbs_gtsam4.3/src/glim_ros1/src/glim_ros/cbs_bridge.cpp) tracks `(from_index,to_index)` under its fixed GLIM source ID from the normal first publication; each logged row carries the complete source-qualified BeliefID. After each later smoother update while **both** endpoint keys still exist, it recomputes `T_i.between(T_j)` from `calculateEstimate` and recomputes the dense 6×6 covariance from `jointMarginalInformation` through the **same** `relative_pose_covariance::compute(..., "schur_relative_between")` construction used for revision 0. Any mean or covariance change beyond `1e-12` emits an increasing revision and logs source ID, indices, physical endpoint stamps, ROS simulated record stamp, current smoother index, `[phi,rho]` mean, and all 36 covariance entries. It retires the tracked pair once either endpoint disappears. This logging path does not republish a ROS CBS belief or change a source factor. [The converter](tools/eig2_revision_stream_export.py) is the diagnostic transport into the receiver: it takes revision 0 from the recorded ROS bag (its actual bag record timestamp), later versions from the source log (their availability stamps), validates them, and produces immutable [first/revision/oracle/finalized CSVs](/home/yeranis/repos/V4RL/cbs_gtsam4.3/runs/_eig2_glim_full_revision_20260923/revision_products). **This validates offline causal replacement semantics, not a deployed live ROS revision wire protocol or network latency.**

The final 51 source poses had not left the source lag at shutdown and are excluded rather than called finalized. On the 590 retained IDs there are **28,608** complete revision messages: 48.49 mean, 48 median, 49 maximum versions per ID. The actual source log has 29,290 later-revision rows over the full 641-edge run; only the fully retired common population is used for scoring. All 28,608 retained covariances are finite, symmetric, and positive definite. Covariance was recomputed for every later version, not carried from revision 0. Median rotational/translation trace evolves from `8.624e-9 rad² / 2.525e-6 m²` at first publication to `6.552e-9 rad² / 1.602e-6 m²` at last valid revision; median last/first ratios are **0.787 / 0.640**. **Last-valid is not mathematically identical to both-endpoint finalized.** The older endpoint exits the fixed-lag smoother about 0.20 s before the newer one. Once that happens the same-snapshot *joint marginal covariance* cannot be recomputed, so the diagnostic stops. The last valid mean differs from the offline both-finalized mean by 0.0661 mm translation RMS / 0.620 mm maximum and 0.000522° rotation RMS / 0.00421° maximum. R3 uses R2's latest available covariance and the later finalized mean; it does **not** claim a nonexistent jointly finalized source covariance. R2/R3's close but non-identical graph trajectories are expected from this real endpoint difference, not a failed factor-replacement test.

## Native iSAM2 replacement path

The opt-in `--revision-beliefs` path in [GrandTourCsvReplay.cpp](online_fgo/src/offline_process/GrandTourCsvReplay.cpp) requires GLIM-only, record-time timeline, and full iSAM2; the existing mode stays the R0 reference. The ledger key is explicitly `(source,from_index,to_index)` and holds the latest revision, current persistent factor index, endpoints, and latest measurement pointer (which contains mean and covariance). The source endpoint keys are the **same exact support poses** used by the original 0.20 s beliefs. No interpolation or topology change enters this EIG-2 test.

For an unseen ID, exactly one `BetweenPose3Factor` with the native full 6×6 covariance is added. For a newer revision, one atomic native `ISAM2::update(new_graph, {}, {old_factor_index}, ..., force_relinearize=true)` removes its previous nonlinear factor and adds the new one; `ISAM2Result::newFactorsIndices[0]` becomes the persistent ledger index. `relinearizeSkip=1`, original `relinearizeThreshold=0.01`, QR, and `findUnusedFactorSlots=true` remain the replay's settings. Duplicate and stale revisions return before a graph update. Full iSAM2 retains historical endpoint variables; this audit does **not** show that the same replacement is safe after fixed-lag marginalization. The actual final graph has **1,776 active factors = 4 priors + 2×591 motion factors + 590 GLIM factors**, not 28,608 GLIM factors.

The two-pose synthetic [replacement test](tools/eig2_isam2_factor_replacement_test.cpp) and five-pose overlapping-factor test both match a clean graph with only the latest factors: maximum SE(3) pose errors `3.4e-16` and `4.9e-14`, with no extra active factor. The [end-to-end smoke test](tools/eig2_revision_receiver_smoke.py) inserts four overlapping source beliefs, replaces each, injects one duplicate and one stale revision, verifies an identical trajectory to the no-duplicate run, and verifies an invalid covariance is rejected **before** output/state creation. The real run had zero duplicate/stale arrivals and no rejected revision; those branches were tested synthetically.

## Causal convergence, cost, and preservation

R0 and R1 respect record availability. R1's revision 0 becomes available after a median **0.119 s** from its physical end (range 0.100–0.158 s); the final jointly valid revision arrives after median **4.854 s** (mean 4.869 s, p95 4.936 s, maximum 4.958 s). The source issued a median **483** revision messages per occupied record second (peak **538**). At the end, 590 revised beliefs are active in the ledger. There were 590 factor insertions, **28,018 removals/replacements**, no double-counting, and no GNSS/Kimera factors. R2/R3 are explicitly noncausal physical-time controls; they are not online performance claims.

Per-revision iSAM2 update time is median **0.342 ms**, mean **1.195 ms**, p95 **5.341 ms**, maximum **12.206 ms**; these 28,608 updates total **34.87 s**. Entire R1 replay took **38.42 s wall** versus R0's **3.31 s** on this machine. The instantaneous correction at the current support pose has median/mean/p95/max **0 / 0.231 / 1.500 / 42.90 mm**; at the revised belief's end pose **0.00185 / 0.164 / 0.624 / 39.51 mm**. These are per-revision sample-pose corrections, not an entire-trajectory norm. The [per-revision event CSV](/home/yeranis/repos/V4RL/cbs_gtsam4.3/runs/_eig2_glim_full_revision_20260923/revision_products/full_r1b/revision_events.csv) records factor indices, timing, correction, and active-factor count.

Raw same-gauge final trajectory separation is R1–R0 **0.0891 m RMS / 0.232 m maximum**, R1–R2 **0.000852 m RMS / 0.00297 m maximum**, and R2–R3 **0.00118 m RMS / 0.00217 m maximum**. The pose-only R1 replacement graph and a clean last-revision graph differ by only **0.0297 mm RMS / 0.0552 mm maximum** in position. The small nonzero full R1–R2 difference also includes a different iSAM2 insertion order and the fact that IMU support-state initializations are made from each graph's then-current estimate; native factor replacement was proven independently by the clean synthetic graph test.

The online current-pose trajectories were saved *as playback progressed*, before late revisions had all arrived. Using one fixed no-scale SE(3) alignment **per complete online trajectory**, cumulative matched-prism RMSE at 10/30/55/59.1 s is R0 **0.0426/0.0410/0.0488/0.0530 m** versus R1 **0.0267/0.0199/0.0213/0.0217 m**. [All 5 s bins](/home/yeranis/repos/V4RL/cbs_gtsam4.3/runs/_eig2_glim_full_revision_20260923/revision_products/online_ate_vs_playback.csv) show a causal improvement, but the final R1 graph's 0.0114 m ATE is a **retrospectively revised** trajectory. The alignment uses each complete online trajectory for evaluation only; it is not an estimator input.

Stop here; topology, covariance weighting, and fusion remain untouched.
